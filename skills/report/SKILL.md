Generate a polished, interactive HTML report for: $ARGUMENTS

## Overview

You are a report generator. You produce self-contained, single-file HTML reports that look like professional dashboards. Reports are designed for local viewing in a browser — not deployed to the web.

Reports **auto-detect the OS theme** (light or dark) and default to that, with a manual toggle button to override. They use a consistent design system, semantic HTML, and interactive elements (collapsible sections, checkboxes, filters, tabs).

## Step 1: Understand the Request

Parse `$ARGUMENTS` to determine what the user wants. The input can be:

| Input Type | Example | Action |
|-----------|---------|--------|
| Topic / description | "Builder's Loft launch week" | Gather context from project files, Notion, calendar, etc. |
| File path(s) | "from ROADMAP.md and package.json" | Read specified files and visualize their content |
| Glob pattern | "notes/research/strata/*.md" | Read matching files and synthesize |
| Data dump | (user pastes data in the conversation) | Structure and visualize the provided data |
| Empty | (no args) | Ask: "What should this report cover? Give me a topic, file paths, or describe what you want to see." |

**Context gathering:** Look at the current working directory. Read relevant files:
- `ROADMAP.md`, `CLAUDE.md`, `package.json` — project context
- Any files the user referenced in conversation
- Notion, calendar, or other MCP data if the topic requires it

**Do not fabricate data.** Every number, date, status, and item in the report must come from a real source (file, API, conversation context). If you lack data for a section, omit it or mark it as "No data available."

## Step 2: Plan the Report Layout

Based on the gathered content, select which sections to include. A report always has:

1. **Header** — Title, subtitle/date, status badges
2. **Stat cards row** — 3-6 key metrics at a glance

Then 2-6 of these section types, chosen based on data:

| Section Type | Use When | Component |
|-------------|----------|-----------|
| **Sprint / Week Calendar** | Date-sequenced tasks this week | Day columns with task items |
| **Timeline** | Chronological events or milestones | Vertical timeline with dots |
| **Issue / Task Table** | Trackable items with status | Table with priority badges and status |
| **Checklist** | Scope items, to-dos, audits | Checkbox list with categories |
| **Comparison Matrix** | Evaluating options side by side | Table with check/cross marks |
| **Score Bars** | Rated/scored items | Horizontal bar chart |
| **Content Calendar** | Scheduled content or posts | Date + title + platform badge list |
| **Cost / Budget Table** | Financial data | Table with highlighted totals |
| **Progress Tracker** | Phase completion | Progress bars with labels |
| **Card Grid** | Collection of items with metadata | Filterable grid of cards |
| **Tabs** | Multiple distinct views of the data | Tab bar with switchable panels |
| **Collapsible Section** | Dense content that's useful but not primary | Expand/collapse with arrow |
| **Callout / Banner** | Key principle, warning, or highlight | Colored banner box |
| **Key-Value List** | Configuration, settings, metadata | Two-column definition list |

**Footer** — "Generated by Claude Code — [date] — Data from [sources]"

## Step 3: Generate HTML

Generate a single self-contained HTML file. All CSS and JS inline. No external dependencies.

### HTML Structure

```html
<!DOCTYPE html>

  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>[Report Title]</title>
  <style>/* All CSS here */</style>

<body>
  <div class="report">
    <header class="header">...</header>
    <div class="stats-row">...</div>
    <main>
      <!-- sections -->
    </main>
    <footer class="footer">...</footer>
  </div>
  <script>/* All JS here */</script>
</body>
</html>
```

### JavaScript

Always include these interactive behaviors:

```javascript
// Auto-detect system theme, then allow manual toggle
document.addEventListener('DOMContentLoaded', () => {
  const html = document.documentElement;
  const toggle = document.querySelector('.theme-toggle');

  // Initialize from OS preference
  if (window.matchMedia('(prefers-color-scheme: dark)').matches) {
    html.setAttribute('data-theme', 'dark');
    if (toggle) toggle.textContent = 'Light';
  }

  // Listen for OS theme changes (user switches system theme while report is open)
  window.matchMedia('(prefers-color-scheme: dark)').addEventListener('change', (e) => {
    if (!html.hasAttribute('data-theme-manual')) {
      html.setAttribute('data-theme', e.matches ? 'dark' : 'light');
      if (toggle) toggle.textContent = e.matches ? 'Light' : 'Dark';
    }
  });

  // Manual toggle (overrides OS preference)
  if (toggle) {
    toggle.addEventListener('click', () => {
      const isDark = html.getAttribute('data-theme') === 'dark';
      html.setAttribute('data-theme', isDark ? 'light' : 'dark');
      html.setAttribute('data-theme-manual', 'true');
      toggle.textContent = isDark ? 'Dark' : 'Light';
    });
  }

  // Collapsible sections
  document.querySelectorAll('.collapsible-trigger').forEach(trigger => {
    trigger.addEventListener('click', () => {
      const expanded = trigger.getAttribute('aria-expanded') === 'true';
      trigger.setAttribute('aria-expanded', String(!expanded));
      const content = trigger.nextElementSibling;
      if (content) content.hidden = expanded;
    });
  });

  // Tabs
  document.querySelectorAll('.tab-btn').forEach(btn => {
    btn.addEventListener('click', () => {
      const group = btn.closest('.tabs') || btn.parentElement;
      const panels = group.nextElementSibling?.parentElement || group.parentElement;
      group.querySelectorAll('.tab-btn').forEach(b => { b.classList.remove('active'); b.setAttribute('aria-selected', 'false'); });
      btn.classList.add('active');
      btn.setAttribute('aria-selected', 'true');
      const target = btn.getAttribute('data-tab');
      panels.querySelectorAll('.tab-panel').forEach(p => {
        p.classList.toggle('active', p.id === target);
      });
    });
  });

  // Filter buttons
  document.querySelectorAll('.filter-bar').forEach(bar => {
    bar.querySelectorAll('.filter-btn').forEach(btn => {
      btn.addEventListener('click', () => {
        const isAll = btn.getAttribute('data-filter') === 'all';
        if (isAll) {
          bar.querySelectorAll('.filter-btn').forEach(b => b.classList.remove('active'));
          btn.classList.add('active');
        } else {
          bar.querySelector('[data-filter="all"]')?.classList.remove('active');
          btn.classList.toggle('active');
          if (!bar.querySelector('.filter-btn.active')) {
            bar.querySelector('[data-filter="all"]')?.classList.add('active');
          }
        }
        // Emit custom event for filtering logic
        const active = [...bar.querySelectorAll('.filter-btn.active')].map(b => b.getAttribute('data-filter'));
        bar.dispatchEvent(new CustomEvent('filter', { detail: { filters: active } }));
      });
    });
  });

  // Score bar animations
  document.querySelectorAll('.score-fill').forEach(bar => {
    const target = bar.getAttribute('data-width');
    if (target) setTimeout(() => { bar.style.width = target; }, 100);
  });

  // Progress bar animations
  document.querySelectorAll('.progress-fill').forEach(bar => {
    const target = bar.getAttribute('data-width');
    if (target) setTimeout(() => { bar.style.width = target; }, 100);
  });
});
```

Add additional JS as needed for the specific report (search, custom filters, calculators).

### Security Rules

- Use `textContent` for dynamic text — NEVER `innerHTML` with data from files
- Use `createElement` + `appendChild` for dynamic DOM
- All event listeners via `addEventListener`, not inline `onclick`/`onchange`
