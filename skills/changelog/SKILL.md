Generate a changelog from git commits since the last tag or a custom starting point.

Arguments: $ARGUMENTS (optional: tag name, commit hash, or date like "2026-04-01" to start from)

## Steps

1. **Find starting point** — Determine what to diff against:
   - If `$ARGUMENTS` is provided, use it as the starting point (tag, commit hash, or date)
   - If no argument, find the most recent git tag: `git describe --tags --abbrev=0 2>/dev/null`
   - If no tags exist, use the last 30 days: `git log --since="30 days ago"`
   - Show the range: "Generating changelog: v1.2.0 → HEAD (or date range)"

2. **Gather commits** — Run:
   ```
   git log <start>..HEAD --pretty=format:"%h|%s|%an|%ar" --no-merges
   ```
   Also get merge commits separately for PR numbers:
   ```
   git log <start>..HEAD --merges --pretty=format:"%h|%s"
   ```

3. **Categorize commits** — Group by type based on commit message prefixes:
   - `feat:` / `feature:` → **Features**
   - `fix:` / `bugfix:` → **Bug Fixes**
   - `refactor:` → **Refactors**
   - `docs:` → **Documentation**
   - `style:` / `ui:` → **UI/Style**
   - `perf:` → **Performance**
   - `test:` → **Tests**
   - `chore:` / `build:` / `ci:` / `deps:` → **Chores**
   - No prefix → Classify by reading the message (e.g., "Update X" → Chores, "Add X" → Features, "Fix X" → Bug Fixes)

4. **Extract PR numbers** — Look for patterns like `(#123)`, `Merge pull request #123`, or GitHub merge commit formats.

5. **Format output** — Generate clean markdown:

   ```markdown
   ## Changelog: v1.2.0 → HEAD
   **14 commits** by 2 authors | April 28 – May 8, 2026

   ### Features
   - Add event capacity limits with waitlist support (#47) — abc1234
   - Member tag filtering on directory page (#45) — def5678

   ### Bug Fixes
   - Fix timezone handling in cron job scheduler (#48) — 123abcd
   - Correct Stripe webhook signature validation (#46) — 456defg

   ### Chores
   - Upgrade Next.js to 16.1.2 — 789hijk
   - Update Drizzle ORM to 0.38 — abc4567

   ---
   *Generated by `/changelog` on May 8, 2026*
   ```

6. **Offer actions** — Ask if the user wants to:
   - Copy to clipboard
   - Write to `CHANGELOG.md` (prepend to existing or create new)
   - Create a GitHub release with this content (`gh release create`)
   - **Do not write or publish without confirmation**

## Notes
- Works best with conventional commit messages (feat:, fix:, etc.)
- For repos without tags, pass a date or commit hash as argument
- Does not modify any files by default — output only
